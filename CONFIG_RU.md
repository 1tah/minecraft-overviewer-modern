# Настройка карты: миры, границы, вид и маркеры

## Где редактировать

В каталоге исходников создайте свою копию примера:

```bash
cp example_config.py render_config.py
nano render_config.py
```

Это Python-файл в UTF-8. Сохраняйте кавычки, запятые и отступы.
В nano: Ctrl+O, Enter — сохранить; Ctrl+X — выйти.
Запуск использует именно файл после `-c`:

```bash
source .venv/bin/activate
python overviewer.py -c render_config.py -p 4 --memory-limit 4G
```

Пути ниже примерные: замените `USER` своим именем пользователя Ubuntu.

## Пути к мирам, результату и текстурам

```python
worlds['CublayCraft'] = '/home/USER/world-snapshot'
outputdir = '/home/USER/minecraft-map'
texturepath = '/home/USER/assets/1.21.5.jar'
webprogress = True
```

`worlds` содержит названия миров в меню и их каталоги с `level.dat`.
`outputdir` — отдельный каталог создаваемого сайта, который должен раздавать
HTTP-сервер. `texturepath` — официальный клиентский JAR нужной версии;
мир ZIP или серверный JAR не заменяют клиентские текстуры.
Обычно JAR установленного клиента находится в Windows по пути
`%APPDATA%\.minecraft\versions\1.21.5\1.21.5.jar`; скопируйте его в Ubuntu.
Для 26.3 укажите свой клиентский JAR 26.3. Новые блоки берутся из его моделей.

Используйте копию мира после штатного сохранения/остановки сервера или согласованный
снимок. В WSL копирование в `/home/USER` обычно быстрее рендера через OneDrive.
Программа не создаёт новые чанки Minecraft: показывает уже сгенерированные.

Обычный одиночный мир: все три рендера ссылаются на один `worlds['CublayCraft']`,
измерение выбирает поле `dimension`: `overworld`, `nether`, `end`.
Для Paper/Bukkit с отдельными каталогами:

```python
worlds['CublayCraft-Overworld'] = '/home/USER/world'
worlds['CublayCraft-Nether'] = '/home/USER/world_nether'
worlds['CublayCraft-End'] = '/home/USER/world_the_end'
renders['overworld']['world'] = 'CublayCraft-Overworld'
renders['nether']['world'] = 'CublayCraft-Nether'
renders['end']['world'] = 'CublayCraft-End'
```

Этот блок добавьте **после** определений `renders` в примере.
Корневой каталог Nether содержит `level.dat` и `DIM-1`, End — `level.dat` и `DIM1`.
Сохраняйте структуру вашего снимка мира.

## Слои и внешний вид

Каждый `renders['имя']` создаёт слой и подкаталог сайта. После первого большого
рендера сохраняйте эти имена: новое имя создаст новый слой с новым рендером.

```python
renders['overworld'] = {
    'world': 'CublayCraft',
    'dimension': 'overworld',
    'title': 'День',
    'rendermode': [Base(), EdgeLines(), SmoothLighting(strength=1)],
    'defaultzoom': 4,
    'center': (0, 80, 0),
}
```

| Параметр | Назначение |
|---|---|
| `world` | Название записи из `worlds` |
| `dimension` | Измерение Minecraft |
| `title` | Название слоя в переключателе |
| `center: (X,Y,Z)` | Начальный центр; ссылка с координатами может переопределить его |
| `defaultzoom: 4` | Начальный масштаб, ограничивается доступными уровнями карты |
| `minzoom: 0` | Насколько можно отдалить |
| `maxzoom` | Верхний предел масштаба; обычно не указывайте |
| `northdirection: 'upper-left'` | Направление севера: также upper-right, lower-left, lower-right |
| `showspawn: True` | Показывать точку появления мира |
| `showlocationmarker: True` | Показывать указатель координат из ссылки |
| `imgformat: 'png'` | Формат тайлов; PNG удобен для чётких текстур |
| `bgcolor: '#1a1a1a'` | Цвет пустых участков |
| `poititle: 'Места'` | Название списка групп маркеров |

`Base()` рисует блоки, `EdgeLines()` подчёркивает грани, `SmoothLighting()` добавляет
освещение. Для Nether пример использует:

```python
'rendermode': [Base(), EdgeLines(), Nether(), SmoothLighting(strength=0.5), Depth(max=47)],
```

Это срез по высоте Y=47, чтобы видеть под крышей. Для End:

```python
'rendermode': [Base(), EdgeLines(), SmoothLighting(strength=0.5)],
```

В старом вашем Overworld был `Depth(max=254)`. Для точного повторения добавьте
его к списку примитивов Overworld. Без него видны и постройки выше Y=254.
Изменение вида, направления севера или текстур может потребовать полного пересчёта.

## Размер и границы карты

Размер задают координаты Minecraft, а не ширина HTML в пикселях:

```python
renders['overworld']['crop'] = (-5000, -5000, 5000, 5000)
renders['nether']['crop'] = (-625, -625, 625, 625)
```

Порядок: `(Xmin, Zmin, Xmax, Zmax)`, в блоках своего измерения.
Overworld в этом примере — примерно 10 000 × 10 000 блоков. Соотношение 8:1 для
Nether указано вручную, автоматически crop между измерениями не пересчитывается.
Граница обработки округляется до чанков; незагруженная территория остаётся пустой.
Без `crop` обрабатывается вся существующая территория измерения.
Можно задать несколько прямоугольников списком кортежей, но для начала используйте один.

`maxzoom=11` не добавит детализацию маленькому миру: число уровней зависит
от охвата карты. Ширина обычного блока при полном масштабе — около 24 пикселей;
тайл — 384 × 384. Чем больше охват, тем больше обзорных уровней и дольше рендер.
При росте границ переход каталогов журналируется, однако новые участки всё равно
нужно отрисовать. При уменьшении границ лишняя территория может быть удалена.
Делайте копию результата перед существенной сменой границ или структуры слоёв.

## Ручные маркеры: города, базы, порталы

В `example_config.py` уже есть функция `manual_marker` и пустой список маркеров
Overworld. Найдите `manualpois` и добавьте свои координаты:

```python
renders['overworld']['manualpois'] = [
    {'id': 'manual', 'x': 120, 'y': 72, 'z': -340,
     'name': 'Спавн', 'description': 'Главная площадь'},
    {'id': 'manual', 'x': -580, 'y': 65, 'z': 900,
     'name': 'База', 'description': 'Вход со стороны реки'},
]
```

Это примерные координаты, замените своими. Вручную созданные маркеры не требуют
сканирования всех чанков. После рендера или после изменения только маркеров:

```bash
python overviewer.py --genpoi -c render_config.py --skip-scan --skip-players -p 1
```

Команда создаёт `markers.js`, `markersDB.js`, `baseMarkers.js` в outputdir.
Обновите страницу браузера. Она не перерисовывает тайлы и сохраняет только ручные
POI при этих флагах: прежние автоматически найденные маркеры в них не сохраняются.
Генератор POI запускайте после завершения основного рендера, чтобы два процесса
не меняли веб-файлы одновременно. Лимит `--memory-limit` относится к основному
рендеру; у режима `--genpoi` свой набор аргументов.

Чтобы разместить такие же маркеры в Nether, добавьте после его рендера:

```python
renders['nether']['markers'] = [
    {'name': 'Порталы', 'filterFunction': manual_marker,
     'icon': 'markers/marker_home.png', 'checked': True},
]
renders['nether']['manualpois'] = [
    {'id': 'manual', 'x': 15, 'y': 47, 'z': -42,
     'name': 'Портал', 'description': 'Переход в основной мир'},
]
```

Координаты здесь относятся к Nether. Каждому слою назначайте свой `manualpois`.
`checked=True` включает группу по умолчанию; `False` оставляет её в списке выключенной.
Для нескольких групп создайте отдельные функции-фильтры по `id`, например
`town` и `portal`, и отдельные записи в `markers`.

Для своих иконок добавьте глобально в конфиг:

```python
customwebassets = '/home/USER/map-assets'
```

Создайте `/home/USER/map-assets/markers/town.png`; в группе задайте
`'icon': 'markers/town.png'`. После изменения файлов выполните:

```bash
python overviewer.py -c render_config.py --update-web-assets
python overviewer.py --genpoi -c render_config.py --skip-scan --skip-players -p 1
```

Иконка должна иметь доступный по HTTP путь внутри outputdir; формат PNG удобен.
Не указывайте вместо URL путь `/home/USER/...` в поле `icon`.
Для автоматических маркеров табличек/игроков нужны свои фильтры и запуск `--genpoi`
без соответствующих skip-флагов. Такой обход читает мир и может быть долгим.

## Обновление, остановка и публикация

Обычный запуск одной и той же командой продолжает сохранённый план либо обновляет
изменившуюся территорию. Не добавляйте `--forcerender` при каждом запуске.
Сохраняйте outputdir целиком, включая скрытые SQLite-журналы.
Изменения конфига/кода/текстур могут сделать старый план несовместимым — это
не повторное выполнение уже сохранённого плана с теми же настройками.

Второй терминал для просмотра (тот же outputdir):

```bash
.venv/bin/python -m http.server 8080 --bind 127.0.0.1 --directory /home/USER/minecraft-map
```

Откройте http://localhost:8080/. При работающем Nginx раздавайте этот каталог
через него. После генерации сервер должен продолжать работать. Во время рендера
статус обновляется автоматически, готовые тайлы подгружаются примерно раз в 15 секунд.
При 100% остаётся компактное сообщение без полосы и времени ожидания.
Ссылки Overviewer/Leaflet в углу карты убраны; лицензии библиотек сохранены в исходниках.

Общий статус генерации одинаков на всех открытых мирах и слоях. Он показывает
суммарный прогресс текущего плана и миры/слои, в которых ещё есть задания.
Готовый дневной слой продолжает показывать общий рендер, если обновляется ночь
или другой мир. Завершённые и пропущенные слои исключаются из списка.
Если повторный запуск не нашёл изменений, вместо «0 из 0» появляется
«Карта актуальна · Изменений для рендера нет».
