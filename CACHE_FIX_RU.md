# Один воркер при большом файловом кэше: исправление

Исправлено в 26.3+resume.10. Общая RAM cgroup включает файловый кэш Linux.
Старый подбор запрещал рост при 72% общего расхода, даже когда значительная часть
этой памяти могла освобождаться ядром. Новый подбор отдельно оценивает рабочую
память и неактивный потенциально чистый файловый кэш. Лимит RAM ядра сохраняется.

## Для уже начатого рендера прежней сборки

Скачайте отдельный `fix_memory_cache.py` из Assets выпуска .10 и положите
в существующий каталог `CublayCraft-Overviewer` на сервере.

1. В консоли работающего рендера нажмите Ctrl+C и дождитесь выхода.
2. Выполните из существующей папки сборки:

```bash
cd /media/disk/overviewer/CublayCraft-Overviewer
./runtime/bin/python3 ./fix_memory_cache.py .
./overviewer.py --config=./configNew.py --cpu-limit=10 --memory-limit=10G
```

Используйте свой прежний конфиг и outputdir. При продолжении не добавляйте
`--forcerender` или `--discard-resume`.

Патч добавляет модуль рядом с `app/overviewer.py` и его подключение в точку входа.
Он не меняет `app/overviewer_core`: эти файлы определяют ключ совместимости
журнала. Контрольная сумма core проверяется до и после установки. Сохраняется
резервная копия `app/overviewer.py.before-cache-fix.bak`. Повторная установка допустима.

При запуске появится `Cache-aware memory policy enabled`. Номер версии в
приветствии сохраняется: исправление подтверждает отдельная строка.
Для существующего совместимого плана ожидается `Resuming ... skipping chunk/tile scan`.
Подготовка текстур выполняется при каждом запуске. Если до прерывания журнал
ещё не был создан, первоначальный анализ потребуется выполнить снова.

Патч действует после перезапуска; уже работающий процесс продолжает старую политику.
Полная новая сборка предназначена также для новых установок, но изменение core
при полном обновлении может сделать старый план несовместимым. Для текущего
незавершённого плана предназначен именно отдельный патч.

## Проверка

- Разбор cgroup v1 проверен на опубликованных пользователем счётчиках:
  RSS 2 505 613 312, cache 7 653 220 352, inactive_file 6 151 872 512 байт.
  При исходном расходе RSS+cache оценка рабочего расхода составляет
  4 006 961 152 байт; правило допускает следующий процесс с RSS 1 507 392 КиБ.
- Проверены total_* v1, dirty/writeback/shmem, отсутствующая статистика,
  ограничение вычета текущим расходом и сокращение пула при анонимном давлении.
- На настоящей cgroup v2 с лимитом 384 MiB файловый кэш заполнил более 72%
  бюджета. Исправленный пул вырос выше одного процесса и выполнил 241 задачу
  без OOM. Ядро удержало общий пик в пределах заданного лимита.
- На реальном частичном рендере 26.3 проверены установка патча, неизменность
  ключа журнала и продолжение оставшихся 286 тайлов без сканирования мира.
- Полный запуск на ядре cgroup v1 удалённого сервера требует проверки там;
  локальная интеграционная проверка выполнена на ядре cgroup v2.

Вычет кэша — консервативная оценка, а не гарантия мгновенного освобождения страниц.
Остаются резерв, ограничение запуска одного нового процесса за раз и OOM-повторы
с меньшим пулом. Глобальная очистка кэша, отключение защиты памяти и изменение
параметров Minecraft-сервера для этого исправления не требуются.
