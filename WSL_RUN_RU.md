# Проверенный запуск в Ubuntu WSL 2

24 октября 2026 выполнены сборка и реальная генерация тестовых миров Minecraft
Java 1.21.5 в Ubuntu 26.04.1, WSL 2. Среда: Python 3.14.4, GCC 15.2,
NumPy 2.3.5, Pillow 12.3.0, systemd 259, Linux kernel 6.6.87.2 WSL.

## Что проверено

* Linux: 157 тестов прошли, один старый тест пропущен. В Linux доступны три
  метода multiprocessing, поэтому проверок больше, чем на Windows.
* Основной мир, Нижний мир и Край: общий запуск выполнил 5295 заданий.
  Работали четыре процесса рендера, общий предел cgroup — 4 GiB, swap запрещён.
* Изолированный OOM-тест: группа с `MemoryMax=128M` при попытке затронуть
  512 MiB памяти завершена ядром. `Result=oom-kill`, `MemoryPeak=134217728`.
  Рабочая Ubuntu и группа рендера продолжили работу.
* Продолжение в Linux: синтетический мир прерван после 3 из 101 задания.
  Повторный запуск с двумя работниками выполнил оставшиеся 98 без обхода
  чанков/тайлов. SHA-256 и mtime трёх готовых изображений сохранились.

В Python 3.14 Linux по умолчанию использует `forkserver`. Его процесс является
OS-родителем работника, поэтому прежняя проверка `getppid()==coordinator_pid`
преждевременно завершала менеджер. Теперь в этом случае отслеживается sentinel
родительского multiprocessing-процесса. При непосредственном OS-родителе
сохранён `PR_SET_PDEATHSIG`. Добавлена проверка всех доступных start methods.

Для Нижнего мира используется `nether`, для Края — `normal`: первый скрывает
крышу, оба показывают блоки без затемнения от отсутствующего небесного света.
`smooth_lighting` в этих тестовых данных даёт очень тёмные изображения.
Основной мир использует `smooth_lighting`. Это настройки вида, а не отсутствие
текстур новых блоков.

## Повторный запуск подготовленной установки

В уже настроенной Ubuntu текущего компьютера:

```bash
cd ~/minecraft-overviewer-modern-wsl
.venv/bin/python overviewer.py \
  -c ~/overviewer-test-run/render_config.py \
  -p 4 --memory-limit 4G
```

Эта команда обновляет карту инкрементально либо продолжает сохранённый план.
Для обычного повторного запуска не нужны `--forcerender` и `--discard-resume`.
Исходные Windows-миры не изменяются: используются Linux-копии в
`~/overviewer-test-run/worlds/`.

Для запуска веб-просмотра, если текущий сервер остановлен:

```bash
cd ~/minecraft-overviewer-modern-wsl
.venv/bin/python -m http.server 18765 --bind 127.0.0.1 \
  --directory ~/overviewer-test-run/output
```

Откройте `http://localhost:18765` в Windows. Сервер слушает только localhost.
После остановки WSL веб-сервер тоже останавливается; файлы результата остаются.

Результат Linux: `~/overviewer-test-run/output/`.
Windows-копия: папка `wsl_run/output/` исходной рабочей папки проекта.
Журналы и отчёты: `wsl_run/reports/` и `wsl_run/run-info.json`.
Эти тестовые миры, JAR, изображения и локальные пути не входят в Git-репозиторий.

## Новая установка

Основные команды установки зависимостей и сборки приведены в
[BUILD_AND_RUN_RU.md](BUILD_AND_RUN_RU.md). Для WSL исходники, venv, снимки миров
и рабочий результат рекомендуется держать в домашнем каталоге Linux.
Готовый результат можно скопировать в Windows после завершения генерации.

Используйте официальный **клиентский** JAR нужной версии как `texturepath`.
Архив с сохранённым миром и серверный JAR не заменяют клиентские ресурсы.
