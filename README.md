# Minecraft Overviewer: новые блоки, продолжение рендера и веб-прогресс

## Готовый архив для Ubuntu 20.04 x86_64

**[Скачать готовую сборку в Releases](https://github.com/1tah/minecraft-overviewer-modern/releases/latest)**.
Выбирайте `CublayCraft-Overviewer-Ubuntu20.04-x86_64.tar.gz`.
Внутри уже есть Python 3.12, зависимости, скомпилированный модуль и ваш configNew.py
с 9 слоями и 282 маркерами. Системный Python 3.8 менять не нужно.

```bash
tar -xzf CublayCraft-Overviewer-Ubuntu20.04-x86_64.tar.gz
cd CublayCraft-Overviewer
# Положите миры в worlds/ или укажите свои пути в configNew.py.
./START.sh
```

START.sh загрузит официальный клиент 1.21.5, если assets/client.jar отсутствует.
Для 26.3 при отсутствии JAR: `MINECRAFT_VERSION=26.3 ./START.sh`.
Исправление новой палитры 26.3 уже включено — отдельный патч не нужен.
В worlds указывается корень с level.dat; каталог dimensions/minecraft выбирается
генератором по dimension. Для объединённого мира автоматически находятся Nether/End,
если отдельные каталоги сохранений отсутствуют.

Привычный запуск: `./overviewer.py --config=./configNew.py -p=4 --memory-limit=8G`.
В версии 26.3+resume.6 `-p` в автоматическом режиме задаёт максимум работников.
Для Ryzen 5700X, например: `./overviewer.py --config=./configNew.py --cpu-limit=12 --memory-limit=10G`.
По умолчанию генератор начинает с одного работника и регулирует их число по RAM;
после OOM повторяет сохранённый план с меньшим максимумом. Итоговая статистика
и рекомендация сохраняются в `output/render-resources.json`.
Подробности и примеры: [RESOURCE_CONTROL_RU.md](RESOURCE_CONTROL_RU.md).
Начиная с 26.3+resume.7, в веб-статусе отображаются текущая RAM/лимит и число
готовых воркеров/максимум. Обновление идёт примерно раз в две секунды, даже
если тайл ещё не завершён. После окончания показывается пик RAM.
В 26.3+resume.8 статус собран в компактный блок из двух строк; ETA до часа
показывается в минутах, от часа — в формате ЧЧ:ММ.
Итог явно подписывает количество тайлов и показывает время рендера, пик RAM
и максимальное число одновременно готовых воркеров.
В 26.3+resume.10 исправлено удержание одного воркера из-за файлового кэша:
подбор учитывает неактивный потенциально чистый кэш отдельно, сохраняя жёсткий
лимит всей cgroup. Для уже начатого рендера прежней версии есть
[патч с сохранением совместимости журнала](CACHE_FIX_RU.md).
В 26.3+resume.11 автоматический режим печатает обычные строки прогресса с TPS
и процентами до сотых: сообщения запуска воркеров больше не смешиваются с
интерактивной полосой в SSH-терминале. Для прежней установки работает `--simple`.
В 26.3+resume.12 можно задать начальный пул, сохраняя автоматику:
`--start-workers=6 --cpu-limit=10 --memory-limit=13G`.
Первые шесть воркеров инициализируются параллельно после подготовки координатора.
Пределы памяти, уменьшение/рост и OOM-повторы действуют дальше.
Для начатого плана старой сборки — [отдельный совместимый патч](START_WORKERS_RU.md).
Ограничение RAM на старой Ubuntu реализовано launcher через cgroup v1/v2 и может
запросить sudo. Работники сохраняют UID пользователя; при недоступном контроллере
памяти запуск без ограничения не выполняется.

**Code → Download ZIP содержит исходники. Для запуска без сборки берите архив из Releases.**
Все файлы этого комплекта и инструкция:
[deploy/ubuntu20](deploy/ubuntu20/START_HERE_RU.md).
Повторная сборка выполняется вручную через Actions → Build Ubuntu 20.04 ready archive.

Исходники на базе GregoryAM-SP/The-Minecraft-Overviewer. Проверены рендер миров
Java Edition 1.21.5, модели из клиентских JAR 26.3 и 26.4-snapshot-5, восстановление
после остановки и лимит RAM в Ubuntu WSL2. Будущие версии с совместимым форматом
моделей поддерживаются автоматически; специальные модели могут требовать доработки.

## Сборка из исходников в новой Ubuntu / WSL2

Репозиторий приватный: используйте свой вход GitHub для клонирования либо
**Code → Download ZIP** и откройте распакованный каталог в Ubuntu.
В WSL храните исходники, копию мира и результат в `/home/имя`, чтобы избежать
медленной работы через OneDrive и `/mnt/c`.

```bash
sudo apt-get update
sudo apt-get install -y git build-essential python3-dev python3-venv unzip
git clone https://github.com/1tah/minecraft-overviewer-modern.git
cd minecraft-overviewer-modern
python3 -m venv .venv
source .venv/bin/activate
python -m pip install --upgrade pip
python -m pip install -r requirements.txt
git clone --depth 1 --branch 12.3.0 https://github.com/python-pillow/Pillow.git ../overviewer-pillow-headers
export PIL_INCLUDE_DIR="$(cd ../overviewer-pillow-headers/src/libImaging && pwd)"
python setup.py build
cp example_config.py render_config.py
nano render_config.py
```

В конфиге укажите путь к **копии мира**, каталогу результата и официальному
**клиентскому** JAR вашей версии Minecraft. В примере все измерения находятся
в одном обычном сохранении. Для Paper/Bukkit с отдельными `world_nether` и
`world_the_end` в конце примера показаны дополнительные записи `worlds`:
поменяйте также поле `world` у соответствующего рендера.
`Depth(max=47)` в Nether убирает крышу, как на вашей прежней карте.
Для Overworld высота не обрезана; старый срез Y=254 можно вернуть через `Depth`.

Запустите рендер из каталога исходников:

```bash
source .venv/bin/activate
python overviewer.py -c render_config.py -p 4 --memory-limit 4G
```

`-p 4` — максимум четыре рабочих процесса при автоматическом управлении.
`--cpu-limit 4` ограничивает доступные логические CPU через affinity.
`--memory-limit 4G` — общий предел памяти
группы рендера, включая рабочих, с отключённым swap этой группы. Нужны cgroup v2
и работающий systemd не ниже 254; проверено на Ubuntu 26.04 WSL2.
При росте расхода RAM автоматика сокращает число работников, а при наличии
запаса постепенно добавляет. После OOM контроллер повторяет сохранённый план
с меньшим числом работников. Если не помещается даже подготовка/один работник,
нужно увеличить RAM или уменьшить набор слоёв. `--fixed-resources` возвращает
фиксированное число процессов без автоматических повторов.
Первоначальный анализ до создания плана при прерывании выполняется повторно.
Не используйте `--forcerender` для обычного продолжения.

## Смотреть карту во время генерации

Второй терминал Ubuntu (укажите **тот же outputdir**, что в конфиге):

```bash
cd ~/minecraft-overviewer-modern
mkdir -p "$HOME/minecraft-map"
.venv/bin/python -m http.server 8080 --bind 127.0.0.1 --directory "$HOME/minecraft-map"
```

Замените outputdir в конфиге на полный путь `/home/ваш_пользователь/minecraft-map`.
Откройте **http://localhost:8080/** в Windows или Ubuntu.
Overviewer создаёт сайт, а HTTP-сервер раздаёт его: оба процесса должны работать
одновременно, чтобы видеть генерацию. Для публичного домена раздавайте outputdir
через свой Nginx/Apache; встроенный сервер по этой команде доступен локально.

При первом рендере сначала виден экран подготовки текстур и анализа мира.
Затем открывается карта и сквозная строка состояния всей генерации:

```text
Общий рендер · Активный слой: CublayCraft-Nether — Нижний мир · Готово 7599 из 229780 тайлов (3.3%) · Осталось 222181 тайлов · Осталось ~222 мин
```

Состояние опрашивается каждые 2 секунды, тайлы обновляются примерно раз в
15 секунд и по завершении. До создания обзорных тайлов часть карты может быть
пустой; готовые подробные участки появляются по мере рендера. ETA приблизительное,
до первых завершённых тайлов показывается «—». Счётчик включает подробные и
обзорные тайлы текущего плана, поэтому не равен числу чанков.
После обычного прерывания показывается «Прервано», после ошибки — «Ошибка»;
при аварийном убийстве процесса через 90 секунд без heartbeat появляется
«Нет обновлений — возможно, рендер прерван». После завершения сайт остаётся
доступным, пока работает HTTP-сервер. Параметр `webprogress = False` отключает статус.

Если Nginx/CDN кэширует всё, отключите кэш для `/render-progress.json`,
`/index.html` и корня сайта; для JS/CSS и тайлов учитывайте query string.
Для долгого рендера запускайте его в `tmux` или службе: закрытие SSH/Ubuntu-терминала
может остановить запущенные в нём процессы.

## Что находится в репозитории

- `overviewer.py`, `overviewer_core/` — генератор и веб-карта.
- `setup.py`, `requirements.txt` — сборка и зависимости Ubuntu/WSL.
- `example_config.py` — рабочий шаблон конфига.
- `test/`, `contrib/` — проверки и вспомогательные инструменты.
- Русские инструкции, анализ изменений, список файлов поставки и лицензии.

Для проверки после сборки: `python -m pip install pytest pytest-mock`, затем
`python -m pytest -q`. Дополнительная проверка веб-статуса, если установлен Node.js:
`node test/test_webprogress_js.cjs`.

Общий статус генерации одинаков на всех открытых мирах и слоях. Он показывает
суммарный прогресс текущего плана и один активный слой по приросту готовых тайлов.
Готовый дневной слой продолжает показывать общий рендер, если обновляется ночь
или другой мир. При параллельной работе показывается один из обрабатываемых слоёв; весь список очереди не выводится.
Если повторный запуск не нашёл изменений, вместо «0 из 0» появляется
«Карта актуальна · Изменений для рендера нет».
