# Проверка управления ресурсами — 25 октября 2026

Проверено в Ubuntu WSL2 с cgroup v2 и systemd 259, на переносимом Python 3.12.15.
Нативный C-модуль готового архива собран для glibc 2.31 / Ubuntu 20.04.

- Linux: 193 теста пройдено, 1 пропущен. Windows: 186 пройдено, 6 пропущено
  (Linux affinity/адаптивный пул и необязательный тест ресурсов).
- Ресурсы официальных клиентов 1.21.5, 26.3 и 26.4-snapshot-5: модели и состояния.
- Пул с настоящими multiprocessing Pipes: рост, сокращение после текущего тайла,
  повторный рост, зависимости обзорного тайла; 201 задача без дублей/пропусков.
- Исключение рабочего процесса: неподтверждённая задача не отмечается выполненной.
- Пустой план: рабочие процессы не запускаются.
- Профиль: сохраняются рекомендация и безопасный максимум; изменение бюджета
  RAM или максимума процессов сбрасывает старый подбор.
- Нативный launcher: настоящая группа 64 MiB, намеренное превышение RAM,
  kernel OOM, автоматический повтор с 2 вместо 4 процессов и успешное завершение.
  Affinity ограничено 4 CPU; отчёт принадлежит исходному UID пользователя.
- Подготовка/один процесс не помещаются в 64 MiB: одна попытка, понятная ошибка,
  автоматический цикл повторов не начинается.
- Запуск из исходников: systemd scope распознаёт Result=oom-kill и повторяет задачу.
- Реальный C/Python рендер тестового мира 26.3, 401 тайл: искусственный скачок
  памяти при запуске второго работника, остановка cgroup 2 GiB. Автоматический
  повтор с одним работником: `Resuming map: 400 pending tiles; skipping chunk/tile scan`.
  Рендер завершён; сохранён профиль с safe_ceiling=1.
- Реальный короткий рендер 1.21.5: 101 тайл под общей cgroup 4 GiB.
- Веб-ресурсы: настоящий рендер с cgroup 2 GiB публикует расход RAM и готовых
  воркеров; значения обновляются независимо от завершения тайла. После окончания
  текущие воркеры сбрасываются в 0, пик RAM сохраняется. JavaScript проверяет
  формат чисел, инициализацию, финальный статус и скрытие устаревших показаний.
- Учёт файлового кэша: реальные счётчики cgroup v1 пользователя, dirty/writeback,
  shmem, total_* и консервативный откат при отсутствии статистики. Настоящая
  cgroup v2 384 MiB: при заполненном кэшем бюджете пул вырос и выполнил 241 задачу
  без OOM. Отдельный патч сохранил ключ реального частичного плана и продолжил
  286 тайлов без сканирования. Подробнее: [CACHE_FIX_RU.md](CACHE_FIX_RU.md).
- Консоль: псевдотерминал POSIX проверяет совместный вывод прогресса и сообщений
  пула без разрыва строки через carriage return. Авто-режим, --simple-output и
  --simple выбирают строковый observer. Проверены TPS и дробные проценты.

Для повторения привилегированного теста launcher на Linux:

```bash
sudo PROBE_USER="$USER" python3 test/native_resource_probe.py /абсолютный/путь/runtime/bin/python3
```

Он использует временный каталог и отдельную группу 64 MiB, не открывает ваши миры.
`PROBE_USER` должен иметь доступ к указанному переносимому Python.

Интерфейс cgroup v1 реализован, но на реальном ядре удалённого сервера Ubuntu 20.04
этот выпуск ещё не проверялся. Автоматика не гарантирует отсутствие любого OOM:
сохранённый план позволяет повторить работу, если меньший пул помещается в RAM.
