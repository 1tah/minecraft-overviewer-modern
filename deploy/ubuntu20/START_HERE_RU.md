# CublayCraft Overviewer — готовая сборка для Ubuntu 20.04 x86_64

Версия 26.3+resume.5 включает исправление палитры Minecraft 26.3. Дополнительный
fix_palette_26_3.py после распаковки этой версии не требуется.

В архиве находятся скомпилированный генератор, переносимый Python 3.12,
NumPy/Pillow и остальные зависимости. Системный Python 3.8 не меняется.
Docker, активация venv и ручная компиляция на сервере не нужны.

## 1. Распаковать

```bash
tar -xzf CublayCraft-Overviewer-Ubuntu20.04-x86_64.tar.gz
cd CublayCraft-Overviewer
```

Распаковывайте весь архив целиком. Не переносите отдельно только overviewer.py.
Запускайте от обычного пользователя с правом sudo, чтобы результат принадлежал ему.

## 2. Положить миры или указать свои пути

По умолчанию ваш configNew.py ожидает:

```text
worlds/2015/level.dat                 основной мир
worlds/2015/region/                  его чанки
worlds/2015_nether/level.dat          отдельный Nether (Paper/Bukkit)
worlds/2015_nether/DIM-1/region/
worlds/2015_the_end/level.dat         отдельный End (Paper/Bukkit)
worlds/2015_the_end/DIM1/region/
worlds/plotworld/level.dat            Builder
worlds/plotworld/region/
```

Копируйте содержимое сохранений, чтобы level.dat находился непосредственно
в указанных папках, а не на дополнительном вложенном уровне.
Можно вместо копирования отредактировать пути worlds в начале configNew.py:

```bash
nano configNew.py
```

Например: `worlds['CublayCraft-Over'] = '/home/cube/2015'`.
Каталоги можно также заменить символическими ссылками на ваши снимки миров.
Используйте сохранённые согласованные копии миров.

В конфиге сохранены ваши 4 мира, 9 слоёв, все 282 маркера, crop, режимы и ракурсы.
Для сохранений 26.1+ с dimensions/minecraft путь worlds должен вести к корню,
где лежит level.dat. Если отдельные Nether/End отсутствуют, конфиг автоматически
использует корень основного мира, когда в нём найдены соответствующие измерения.
Builder должен существовать. Если он не нужен, удалите его запись worlds и четыре
блока renders['plotworld...']. Миры и новые чанки этот архив сам не создаёт.

## 3. Запустить

Для Minecraft 1.21.5 достаточно:

```bash
./START.sh
```

Если assets/client.jar отсутствует, скрипт скачает официальный клиентский JAR
1.21.5 с серверов Mojang и проверит SHA-1. Для другого клиента, например 26.3:

```bash
MINECRAFT_VERSION=26.3 ./START.sh
```

Этот выбор действует при отсутствии assets/client.jar. Уже имеющийся JAR не
перезаписывается. Можно самостоятельно положить клиентский JAR в assets/client.jar
или указать свой абсолютный texturepath в configNew.py. Серверный JAR и ZIP мира
для текстур не подходят. Для загрузки JAR нужен интернет; игровые файлы в архив
не включены.

Ваш привычный запуск тоже работает, после подготовки текстур:

```bash
./overviewer.py --config=./configNew.py -p=4 --memory-limit=8G
```

Если texturepath указывает на внешний готовый JAR, используйте именно эту команду:
START.sh проверяет стандартный assets/client.jar.
Параметр -p задаёт работников. Для первой проверки используйте 4, не 14.
Лимит RAM относится ко всей группе, а не к одному работнику.
Если --memory-limit не указан, выбирается до 8 GiB и не более 70% RAM сервера.
Явный лимит выше 90% RAM отклоняется, чтобы оставить память системе.
Можно задать, например, --memory-limit=4G или --memory-limit=6G.

## Права и память на Ubuntu 20.04

Лимит создаётся непосредственно через kernel cgroup, без зависимости от нового
systemd. Поэтому запуск может запросить пароль sudo. Sudo нужен для создания
и очистки отдельной группы RAM; сам рендер запускается с исходным UID пользователя.
Неограниченный запуск при ошибке создания/проверки лимита не выполняется.
При запуске сразу от root рендер тоже будет выполняться от root.

Поддерживаются cgroup v1 memory (обычная конфигурация Ubuntu 20.04) и cgroup v2.
В v2 swap группы отключается; в v1 ограничивается memory+swap, если доступен memsw.
Если memsw отключён в ядре, остаётся жёсткий лимит физической памяти и swappiness=0,
о чём выводится сообщение. Ограничение требует доступного контроллера memory.
Если сервер — контейнер/VPS без доступа к созданию cgroup, launcher выдаст ошибку;
тогда ограничение должен предоставить хостинг/администратор хоста.

При OOM останавливается вся наша группа и выводится понятное сообщение. При
наличии файла веб-статуса он обновляется от вашего UID. Автоматическое уменьшение
числа работников не реализовано: уменьшите -p и повторите ту же команду.
Ctrl+C останавливает работу; для продолжения запустите снова без --forcerender.
Начальная подготовка до сохранения плана при прерывании повторяется.

## 4. Смотреть карту

Результат по умолчанию находится в output/. Во втором SSH/терминале:

```bash
cd /путь/к/CublayCraft-Overviewer
./serve.py --bind 127.0.0.1 --port 8080
```

Для удалённого сервера localhost относится к серверу. Пример SSH-туннеля
на вашем компьютере (замените USER и SERVER):

```bash
ssh -L 8080:127.0.0.1:8080 USER@SERVER
```

После этого откройте http://localhost:8080/ на компьютере.
Либо настройте ваш Nginx на каталог output; если outputdir изменён, укажите его
также серверу: `./serve.py --directory /ваш/outputdir`.
Чтобы раздавать встроенным сервером по сети, можно задать --bind 0.0.0.0, но
для постоянного публичного сайта используйте настроенный веб-сервер.
Не раздавайте всю папку сборки: в configNew.py находятся ваши координаты и описания.

Статус сквозной: общий счётчик, ETA и один активный слой по приросту готовых тайлов.
Подготовка занимает время; обзорные тайлы появляются по мере завершения их частей.
После завершения бар и остаток времени скрываются.

## 5. Маркеры

После завершения рендера:

```bash
./overviewer.py --genpoi --config=./configNew.py --skip-scan --skip-players -p=1
```

Будут опубликованы ручные маркеры из конфига. Обновите страницу.
Не запускайте genpoi одновременно с основным рендером.
В output/icons уже лежат иконки для всех ссылок вашего конфига. Четыре изображения
категорий взяты из вашего прежнего комплекта; для шести отсутствовавших использована
встроенная иконка дома. Список — ICONS.txt. Их можно заменить своими PNG с теми же
именами, не меняя конфиг. Если outputdir другой, скопируйте туда каталог icons.

## Проверки и состав

Нативный модуль собран и запущен с библиотеками Ubuntu 20.04 (glibc 2.31), x86_64.
В этой среде выполнен реальный тестовый рендер и генерация POI.
Палитры 26.3 проверены реальным рендером в новом формате и набором 167 тестов
(1 старый тест пропущен). Отдельно проверены перенос в другую папку, запуск от UID обычного пользователя,
рендер с лимитом RAM и OOM только в одноразовой группе cgroup v2.
Ветка cgroup v1 использует интерфейс ядра, но на реальном ядре вашего сервера
пока не проверялась; при недоступных возможностях запуск остановится с ошибкой.
Подробные результаты — BUILD_INFO.json и reports/.

Исходники нашей сборки находятся в app/, launcher и cgroup_runner.py — в корне.
В runtime/ сохранены Python и зависимости с их лицензиями.
Общая лицензия Overviewer — COPYING.txt. Не удаляйте runtime/ и app/.
Пакет не устанавливает библиотеки в системный Python и не меняет загрузку ОС.
Для долгого рендера запускайте команду в tmux/screen, чтобы закрытие SSH её не прервало.
