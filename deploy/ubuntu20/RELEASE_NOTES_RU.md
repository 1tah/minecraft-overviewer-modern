Готовая нативная сборка для Ubuntu 20.04 x86_64. Системный Python менять не нужно.

Новое в 26.3+resume.12: --start-workers=6 запускает параллельную подготовку шести
процессов после подготовки координатора, сохраняя автоматику CPU/RAM и OOM-повторы.
Пример: ./overviewer.py -c ./configNew.py --start-workers=6 --cpu-limit=10 --memory-limit=13G
После OOM повтор с тем же стартовым запросом использует уменьшенный безопасный пул.
Для НЕЗАВЕРШЁННОГО плана старой адаптивной версии скачайте fix_start_workers.py:
после Ctrl+C выполните ./runtime/bin/python3 ./fix_start_workers.py . и повторите
запуск с --start-workers. Патч оставляет core/ключ журнала неизменными.
Проверены настоящий старт шести, OOM-повтор тремя и продолжение старого плана.

Новое в 26.3+resume.11: авто-режим использует строковый консольный прогресс,
чтобы сообщения изменения пула не разрывали интерактивную полосу в SSH.
Сохранены TPS, ETA и количество тайлов; проценты показываются до сотых.
Исправлено распознавание --simple-output; прежний --simple тоже работает.
Для уже работающего рендера старой версии смешанная полоса — косметика:
можно оставить его работать, а --simple добавить при следующем запуске.

Новое в 26.3+resume.10: исправлено удержание одного воркера из-за файлового кэша.
Подбор учитывает чистый неактивный файловый кэш отдельно, сохраняя жёсткий лимит.
Dirty/writeback/shmem и активный файловый кэш остаются в рабочем бюджете.
Для НЕЗАВЕРШЁННОГО рендера старой версии скачайте отдельный fix_memory_cache.py:
он меняет только точку входа и добавляет модуль рядом с ней, оставляя core и ключ
журнала неизменными. После Ctrl+C: ./runtime/bin/python3 ./fix_memory_cache.py .
Затем повторите прежний запуск без --forcerender и --discard-resume.
Проверено продолжение реального частичного плана без сканирования мира.
Полная сборка .10 предназначена для установки/обновления; изменение core при
полном обновлении может сделать незавершённый план старой версии несовместимым.

Новое в 26.3+resume.9: понятный итог «Рендер завершён» с подписанными тайлами,
временем рендера, пиком RAM и максимальным числом использованных готовых воркеров.
Итог относится ко всем слоям. Время рендера не включает подготовку текстур до пула.

Новое в 26.3+resume.8: компактный статус в две строки шириной до 500 px.
Сохранены слой, прогресс, оставшиеся тайлы, ETA, RAM и воркеры.
До часа ETA отображается в минутах, от часа — ЧЧ:ММ (длительность, включая >24 ч).
Полная расшифровка показывается при наведении; (+1) означает запуск воркера.

Новое в 26.3+resume.7: в полосе веб-статуса видны текущая RAM/лимит и число
готовых воркеров/максимум, включая отметку инициализации. Обновление примерно
раз в две секунды независимо от завершения тайлов. По окончании виден пик RAM;
текущие счётчики и полоса скрыты. Старые показания при потере heartbeat скрываются.

Включены Python 3.12, скомпилированный модуль, зависимости, configNew.py CublayCraft,
иконки, общий веб-прогресс и ограничение RAM через cgroup v1/v2.
Исправлено чтение новых палитр Minecraft 26.3: строки, id/properties,
точные значения свойств по умолчанию и смешанные NBT-списки.

Скачайте именно файл CublayCraft-Overviewer-Ubuntu20.04-x86_64.tar.gz ниже.
Распакуйте его, положите миры в worlds/ либо измените пути в configNew.py.
Запустите ./START.sh. При отсутствии assets/client.jar он загрузит клиент 1.21.5;
для 26.3 используйте MINECRAFT_VERSION=26.3 ./START.sh.
Подробная инструкция START_HERE_RU.md находится внутри архива.

Запуск ./overviewer.py --config=./configNew.py -p=4 --memory-limit=8G сохранён.
Sudo используется для создания лимита; рабочие процессы получают ваш исходный UID.
Доступ к контроллеру памяти ядра обязателен. Ограничение cgroup v1 не проверялось
на реальном ядре целевого сервера; недоступный контроллер приводит к отказу запуска.
В этой версии включено автоматическое управление: --cpu-limit=12 --memory-limit=10G
задают максимум логических CPU и суммарный бюджет RAM. Работники добавляются
при запасе памяти и выводятся после текущего тайла при росте расхода.
После OOM контроллер автоматически повторяет сохранённый план с меньшим пулом.
Итоговый render-resources.json содержит статистику, пик RAM и рекомендацию;
.overviewer-autotune.json переносит подбор на следующий запуск.
Прежний -p теперь задаёт верхнюю границу в авто-режиме. Для фиксированного пула:
--fixed-resources -p=4. Подготовка/один работник должны помещаться в лимит.

Миры и игровые JAR в архив не включены. Источник исправления палитры подтверждён
тестовым рендером; пользователь также подтвердил работу патча на своём мире.
